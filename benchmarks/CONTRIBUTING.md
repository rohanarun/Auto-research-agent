# Add a model, harness or score

1. Prepare the same pinned scenario and pass isolation preflight. Use a fresh workspace for every trial. Keep curator downloads outside the timed actor phase.
2. Record exact model ID, reasoning effort, transport, prompt hash, harness source hash, platform, pinned dependencies, research cap and GPU queue policy. Changing prompts, context, tools or hardware requires a new cohort/harness identifier.
3. Preserve immutable in-budget submissions and evaluate them independently. Keep numerical checks, proof review, source-rule compliance and target recovery separate.
4. Submit result JSON, per-case paired timings and source hashes with a concise reproducibility note. Include multiple seeds/trials before drawing model rankings. Do not publish account files, API keys, private references, raw inference homes or unrestricted provider logs.
5. Regenerate charts from data. Missing measurements remain missing; timeout observations remain censored. Explain infrastructure exclusions and deviations instead of deleting inconvenient runs.

New scenarios should pin an exact earlier commit, a verifiable later improvement, complete input hashes, a score direction, an independent correctness evaluator, clear retained assumptions and a predeclared success rule. Check redistribution terms before including upstream source. A generic percentage speedup is not a substitute for the intended historical milestone.
